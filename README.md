# Worka 微信只读便笺

独立 DSH 插件，提供个人微信的本机只读查询。支持 macOS arm64、Worka 0.3、Node 24 和微信 4.x；非腾讯官方接口。

## Agent 初始化

用户点击“一键 AI 初始化”后，由 Agent 完成后台、读取组件、配置和首次读取。无需用户事先安装 Python、Go 或手工创建配置文件。已有微信便笺继续使用原实例，保留会话选择、游标、暂停状态和 AI 开关。

已有便笺直接初始化；尚无便笺时，通过 Worka 的 `note.importPreview` / `note.import` 从 `template` 安装发布便笺，复用随源码提供的预构建界面。

1. Agent 使用宿主原生执行和文件工具，按本仓库的构建脚本准备后台，再通过 `updates.reloadPlugin({packageName,directory})` 加载。宿主提供 Worka 与 DSH peer，插件不安装第二套宿主。
2. 在 checkout 执行 `node runtime/install.mjs`。Worka App 自带 Node/Bun；也可用 Bun 执行。工具下载固定版本的完整运行包，校验归档和文件收据，安装到当前用户的应用数据目录，并原子写入权限为 0600 的 `~/.config/worka-wechat/runtime.json`。不需要管理员权限，不读取消息或密钥，不修改已有密钥配置。
3. 先调用本便笺 `initialize({})`。若尚未完成首次密钥准备，使用安装工具返回的 `bootstrap` 命令及环境运行本版本 wxkey，再继续原便笺的初始化和实际查询。账号登录、手机确认、macOS 原生授权由用户完成；技术诊断和重试由 Agent 执行。首次准备使用系统 LLDB；若系统尚无 Apple 命令行工具，由 Agent 调用系统安装入口完成准备，用户处理必要的系统确认。无需给 CLI 手工添加完全磁盘访问权限。

隔离 profile 或自定义目录可通过 `--root`、`--config`、`--key-config` 指定路径，也可设置对应的 `WORKA_WECHAT_RUNTIME_ROOT`、`WORKA_WECHAT_RUNTIME_CONFIG`、`WORKA_WECHAT_KEY_CONFIG`。读取后台沿用同一 runtime config，确保首次安装和后续读取使用同一用户环境。

安装工具只准备技术环境，不替 Agent 决定业务范围或实现额外初始化状态机。下载、构建或读取失败时保留实际错误，Agent 可检查环境、修复组件并继续，不能只让用户“先把环境装好”。

缺少本机读取初始化文件仅表示首次准备尚未完成，不等于系统拒绝了权限。只有实际出现的微信登录确认或 macOS 原生授权窗口才交给用户处理；不要据此要求完全磁盘访问或关闭系统保护。

没有既有选择时，初始化只接入文件传输助手，实际读取后返回就绪状态和会话计数；不返回正文，不开启 AI 自动处理。之后可在便笺内“选择会话”。已有系统授权和登录直接复用。

便笺入口为 `https://github.com/kllilizxc/dsh-worka-wechat/tree/main/template`。市场安装界面后，初始化任务按上面流程准备后台和组件；界面导入本身不执行组件程序。每个 Worka 宿主目前使用一张微信便笺。

## 组件与更新

`runtime/sources.json` 固定上游来源和 SHA-256，`runtime/patches` 保存可复现修复，`runtime/requirements.txt` 固定 Python 依赖及哈希。运行包包含独立 Python、MCP、wechat-cli、wxkey、WCDB 兼容库、第三方许可证和逐文件收据，不使用构建者的 profile、账号或全局运行环境。

修复包含文件传输助手 ID 识别、轻量状态检查、wxkey 调试器启动和数据库目录收集，以及移除上游管理员密码采集与持久化。保持 SIP 开启，使用独立 shadow 微信，保留原版签名。首次准备可能需要系统授权和微信登录，不保存管理员密码。

更新时 Agent 沿用 Worka 的普通插件更新入口，再运行对应版本的组件安装工具，验证真实读取。旧运行版本与用户数据保留；没有后台时先修复后台，不重复建便笺。错误文案不把超时推断成“微信未登录”或“缺少完全磁盘访问权限”。

开发者在 macOS arm64 上运行 `WORKA_GO_BINARY=/absolute/path/to/go node runtime/build.mjs`，需要 Go 1.26.9 与 Apple 编译工具；接收者安装预构建运行包无需 Go 或编译环境。固定 tag `runtime-v<版本>` 的 GitHub Actions 在空白构建机运行相关回归、构建运行包并验证空白安装后发布资产。发布后把资产的 `release.json` 固定到本仓库，再验证网络安装并推送 main。

## 读取与隐私

数据链路：Worka 后台 → DSH 管理的本机禁网进程 → stdio MCP → CLI → 微信本地数据库。运行时只开放 status、sessions、timeline、read_events；媒体、OCR、语音、文件提取和联网关闭。初始化下载组件发生在 Agent 的安装阶段，读取进程持续禁网。

默认只在本机查看已选会话。用户明确开启 AI 自动处理和连线后，已选会话的新文字消息才进入授权模型；不发送微信回复，不批量交办启用前的历史消息。本人发往其他私聊、群聊的消息不触发连线，文件传输助手按稳定 ID 判断。消息、密钥、联系人、日志和用户配置不进入仓库或发布包。

最多 20 个会话，每个保留最近 200 条，初次读取最近 50 条。消息与游标原子保存，重启沿用去重记录；暂停和卸载停止读取，保留已有资料。

## 验证

运行 `bun run build`、`bun run typecheck`、`bun test tests/backend.test.ts tests/source.test.ts`。构建运行包后执行 `node --test runtime/install.test.mjs`，覆盖空目录、路径含空格、独立 Python、无密钥就绪状态、重试保留配置与密钥、损坏归档保留旧配置。

空白安装验证与真实账号读取分别记录。当前已验证微信 4.1.15 的文件传输助手读取；不能把合成测试或本机空白 profile 当成另一台实体 Mac 的验收，也不承诺所有未来微信版本兼容。

## 全局变化发现

所有刷新入口共享一个消费者及5秒批次频率。重复的已选会话只占一个待办位置；暂停、归档、桌面暂停、账号变化和卸载沿用宿主生命周期。增加会话只补检新选项，取消选择移除它的待办；清空选择后不沿用旧账号的发现位置。

底层全局接口提供会话变化而非逐消息日志，补读继续使用原有消息游标。其时间精度为秒，因此相邻发现窗口重叠边界1秒，稳定 local_id 排除已经读过的消息。空检查仅在内存推进窗口，不改写整份私有聊天文件；重启从已持久化的位置安全重放，未完成的分页和待办继续恢复。全局结果若明确截断或分页未推进则保留位置并报错，不声称已完整同步。发现依赖本机会话活动时间，不保证任意旧记录编辑都会触发自动更新。

安装包中的桥接层对全局结果只保留会话 ID、cursor 和 query，消息读取仍仅限已选会话。原消息缓存上限、AI授权范围、本人发言过滤和本地反馈保持不变。全局发现并不自动授予发送微信或向外部上传资料的权限。
